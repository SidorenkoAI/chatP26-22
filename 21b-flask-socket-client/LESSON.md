# Урок 21b. Веб-клиент для сокет-чата: консоль → страница в браузере

## Цель

Соединить две половины курса самым простым способом. Берём сервер чата из урока 4 и **не меняем в нём ни строчки**. Консольный клиент заменяем маленьким сайтом на Flask: вместо `input()` — форма, вместо `print()` — список сообщений на странице. Браузер и консольные клиенты переписываются в одном чате.

Никаких баз данных, JSON, входа по паролю и JavaScript. Протокол тот же, что в уроке 4: строки текста, разделённые `\n`.

Это урок-мостик. Его можно провести сразу после урока 21 (нужны уроки 1–4 и 19–21) или как разминку перед уроком 24: там та же идея «сайт — посредник между браузером и сервером чата», но с WebSocket, JSON и входом по паролю. Если группа ещё не прошла урок 4, тот же урок на однофайловом чате урока 3 — [урок 21a](../21a-flask-socket-client-simple/LESSON.md).

## Перед началом

- Код урока 4: папки `server/`, `client/`, `common/` переходят **без изменений**.
- Из урока 21 — Flask, формы, POST → redirect → GET. Поставить Flask: `pip install -r requirements.txt`.
- Новые файлы:
  - `app.py` — сайт, он же клиент чата;
  - `templates/index.html` — страница с окном сообщений и формой;
  - `templates/messages.html` — только список сообщений, обновляется сам.
- Три терминала в папке урока: `python -m server`, `python -m client`, `python app.py`.

## Теория (10 минут)

- **Вспомнить клиента урока 4.** Он делает три вещи: подключается к серверу (`connect`), в отдельном потоке печатает всё, что пришло (`print`), а в главном цикле отправляет то, что ввели (`input`).
- **Идея урока.** Сайт на Flask тоже может быть клиентом чата. Он подключается к серверу так же, как консольный клиент. Только пришедшие сообщения он не печатает, а складывает в список, а текст для отправки берёт не из `input()`, а из формы.
  ```
  браузер ──HTTP (форма)──► app.py ──сокет──► сервер урока 4 ◄──сокет── консольный клиент
  ```
- **Почему браузер не подключается к серверу чата сам.** Браузер умеет только HTTP (и WebSocket, урок 24). «Голый» TCP-сокет, как у консольного клиента, ему недоступен. Поэтому посередине — наш сайт: с браузером он говорит по HTTP, с сервером — через сокет.
- **Как новые сообщения попадут на экран без JavaScript.** Сообщения показываем на отдельной маленькой странице, которая сама перезагружается раз в 2 секунды (`<meta http-equiv="refresh">`). Эту страницу вставляем в главную через `<iframe>` — «окно» с другой страницей внутри. Форма снаружи iframe, поэтому набранный текст не пропадает.

## Пошаговый план занятия

1. **Запустить урок 4.** В двух терминалах: `python -m server` и `python -m client`. Написать пару сообщений. Открыть `client/__main__.py` и найти в нём `connect`, `print` и `input`: именно их сейчас и заменим.

2. **Сайт, который только читает.** Создать `app.py`:
   ```python
   chat = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
   messages = []
   lock = threading.Lock()

   def receive_loop():
       for text in iter_lines(chat):
           with lock:
               messages.append(text)

   @app.route("/messages")
   def show_messages():
       with lock:
           shown = list(messages)
       return render_template("messages.html", messages=shown)
   ```
   И `main()`: `chat.connect(...)`, поток с `receive_loop`, `app.run()`. Шаблон `messages.html` пока без тега `<meta http-equiv="refresh">`.

   Запустить `python app.py`. В терминале сервера появился ещё один клиент: это наш сайт. Открыть `http://127.0.0.1:5000/messages`, написать что-нибудь из консольного клиента и нажать F5 в браузере. Сообщение на странице! Половина клиента готова: `print()` заменили страницей.

   Сравнить `receive_loop` с клиентом урока 4: отличается одна строка. И замок, потому что список читают потоки Flask (урок 21).

3. **Отправка.** Добавить форму в `index.html` и маршрут `/send`:
   ```python
   @app.route("/send", methods=["POST"])
   def send():
       text = request.form.get("text", "").strip()
       if text:
           send_line(chat, text)
       return redirect(url_for("index"))
   ```
   На главной — `<iframe src="/messages">` и форма. Отправить сообщение из браузера: оно появилось в консольном клиенте. Вторая половина готова: `input()` заменили формой.

   Обратить внимание: своё сообщение мы в список **не добавляем**. Оно приходит обратно от сервера, как и в консольном клиенте: сервер урока 4 рассылает каждое сообщение всем, в том числе автору.

4. **Автообновление.** Написать что-нибудь из консоли: в браузере ничего не меняется, пока не нажмёшь F5 или не отправишь своё. Добавить в `<head>` шаблона `messages.html`:
   ```html
   <meta http-equiv="refresh" content="2">
   ```
   Теперь сообщения из консоли появляются сами. Начать набирать текст в форме и подождать: текст не стирается, потому что перезагружается только iframe.

   Почему новые сообщения сверху (`messages|reverse`)? После каждой перезагрузки iframe показывает начало страницы. Если бы новые были внизу, их пришлось бы каждый раз прокручивать.

5. **Почему без `debug=True`.** Временно написать `app.run(port=args.web_port, debug=True)` и перезапустить сайт. В терминале сервера — **два** новых клиента! В режиме отладки Flask запускает программу дважды: второй экземпляр следит за изменениями файлов. Значит, и `chat.connect` выполняется дважды. Вернуть как было.

6. **Безопасность.** Из консольного клиента отправить `<b>жирный</b>` и `<script>alert(1)</script>`. В браузере — обычный текст: шаблон экранирует его сам (урок 20). Иначе любой участник чата мог бы выполнить свой JavaScript в браузерах всех, кто сидит через сайт.

7. **Общий чат в классе.** Учитель запускает сервер так, чтобы к нему можно было подключиться с других компьютеров: `python -m server --host 0.0.0.0`. Ученики запускают **свой** сайт и подключают его к серверу учителя: `python app.py --host <IP учителя>`, а потом открывают `http://127.0.0.1:5000/`. Часть класса — в браузере, часть — в консоли, чат один.

8. **Обсудить ограничения.**
   - Сайт — это **один** клиент чата. Откройте его в двух вкладках: сервер видит одного участника, и обе вкладки показывают одно и то же. Поэтому каждый запускает свой сайт у себя.
   - Сообщения подписаны адресом вида `('127.0.0.1', 53211)`. Имена — в задании 1 (пока без изменений сервера) и в уроке 5 (по-настоящему).
   - Перезагрузка каждые 2 секунды — это много лишних запросов (F12 → Network). Как сделать лучше: опрос через `fetch` (урок 22) и WebSocket (урок 24).

## Контрольная точка

- Сообщение, отправленное из браузера, появляется в консольном клиенте, и наоборот.
- Сообщения из консоли появляются в браузере сами, без F5, а набранный в форме текст при этом не пропадает.
- В терминале сервера сайт виден как **один** клиент.
- `<script>` из консоли показан в браузере как текст.

## Частые проблемы

- **`ConnectionRefusedError: [WinError 10061]` при запуске `app.py`.** Сервер чата не запущен или запущен на другом порту. Сначала `python -m server`, потом сайт. Понятное сообщение вместо этой ошибки — задание 4.
- **Сайт ученика не подключается к серверу учителя (`TimeoutError` или `ConnectionRefusedError`).** Сервер запущен без `--host 0.0.0.0`, неверный IP или порт закрыт брандмауэром Windows на компьютере учителя (разрешить Python при первом запуске сервера). Подробно — в `DEPLOY_LAN.md` урока 10.
- **`ModuleNotFoundError: No module named 'common'`.** `app.py` запущен не из папки урока. Перейти в папку урока (там, где лежат `server/` и `common/`).
- **`ModuleNotFoundError: No module named 'flask'`.** Не установлен Flask или не активировано виртуальное окружение: `pip install -r requirements.txt`.
- **В терминале сервера два клиента от одного сайта.** Включён `debug=True` (шаг 5).
- **Текст в форме стирается каждые 2 секунды.** Тег `<meta http-equiv="refresh">` попал в `index.html`, а должен быть в `messages.html`.
- **Внутри iframe открылась вся страница целиком (с формой) или ошибка 404.** В `src` у iframe не тот адрес: нужен `/messages`.
- **Остановили сервер, а сайт при отправке показывает `500 Internal Server Error`.** Сайт пытается писать в закрытое соединение. В окне сообщений при этом есть «Соединение с сервером потеряно». Перезапустить сервер и сайт; аккуратная обработка — задание 4.
- **Своё сообщение появилось не сразу после «Отправить».** Сервер присылает его обратно за доли секунды, а страница иногда успевает загрузиться раньше. Через 2 секунды iframe обновится, и оно появится.
- **`Address already in use` / порт 5000 занят** (на macOS его занимает AirPlay). Запустить сайт на другом порту: `python app.py --web-port 5001`.
