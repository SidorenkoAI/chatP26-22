# Урок 21a. Веб-клиент для сокет-чата урока 3 — теория и разбор кода

В уроке 3 мы общались в чате через консоль: `server.py` и несколько `client.py`. В уроке 21 сделали сайт с формой. Сегодня соединяем одно с другим: сайт на Flask подключается к серверу чата урока 3 и становится его клиентом. Сервер при этом не меняется ни на строчку.

## Как это устроено

```
браузер ──HTTP──► app.py (Flask) ──сокет──► server.py (урок 3) ◄──сокет── client.py
```

- Для **сервера** наш сайт — ещё один клиент, такой же, как `client.py`. Сервер не знает и не должен знать, что за ним стоит браузер.
- Для **браузера** это обычный сайт, как в уроке 21: страницы и форма.

Почему браузер не подключается к серверу чата напрямую? Браузер умеет говорить только по HTTP (и по WebSocket, урок 24). Подключиться к «голому» TCP-сокету, как это делает `socket.connect`, страница в браузере не может. Поэтому нужен посредник — наш сайт.

### Что заменилось, а что осталось

| Что делает клиент | `client.py` (урок 3) | `app.py` (этот урок) |
|---|---|---|
| Подключиться к серверу | `sock.connect((HOST, PORT))` | то же самое |
| Принимать сообщения | поток `receive_loop`, внутри `print(...)` | поток `receive_loop`, внутри `messages.append(text)` |
| Показать сообщения | они уже напечатаны в консоли | страница `/messages` показывает список |
| Отправить сообщение | `text = input("> ")`, потом `sock.sendall(...)` | форма → `POST /send` → `sock.sendall(...)` |
| Протокол | строка + `\n`, кодировка `utf-8` | то же самое |

## Разбор `app.py`

```python
import socket
import threading

from flask import Flask, redirect, render_template, request, url_for

HOST = "127.0.0.1"  # адрес сервера чата
PORT = 5555         # порт сервера чата
WEB_PORT = 5000     # порт нашего сайта
```

Здесь встретились обе половины курса. `socket` и `threading` — из уроков 1–3, Flask — из уроков 19–21. Константы `HOST` и `PORT` такие же, как в `client.py`: куда подключаться. `WEB_PORT` — новое: на каком порту работает сам сайт. Это два разных порта: к 5555 подключаемся мы, к 5000 подключается браузер.

```python
app = Flask(__name__)

sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)

messages = []
messages_lock = threading.Lock()
```

- `sock` — сокет для связи с сервером чата. Он один на весь сайт. Здесь мы его только создаём, а подключаем в `main()`.
- `messages` — всё, что прислал сервер, по порядку. Это просто список строк.
- `messages_lock` — замок, как `clients_lock` в `server.py`. Список меняет поток `receive_loop`, а читают потоки Flask, которые обслуживают запросы браузера. Без замка один поток мог бы читать список в тот момент, когда другой его меняет.

### Приём сообщений

```python
def receive_loop():
    incoming = sock.makefile("r", encoding="utf-8", newline="\n")
    try:
        for line in incoming:
            text = line.rstrip("\n")
            with messages_lock:
                messages.append(text)
    except OSError:
        pass
    with messages_lock:
        messages.append("*** Соединение с сервером потеряно ***")
```

Сравните с `client.py`:

```python
def receive_loop(sock: socket.socket) -> None:
    incoming = sock.makefile("r", encoding="utf-8", newline="\n")
    for line in incoming:
        text = line.rstrip("\n")
        print(f"\n{text}\n> ", end="")
```

Отличие одно: вместо `print` — `messages.append`. Консоль сама «помнит» всё напечатанное, а на сайте мы храним сообщения в списке, чтобы потом показать их на странице.

- `sock.makefile(...)` — как и раньше, превращает сокет в «файл», из которого удобно читать по строкам: каждая строка, до `\n`, — одно сообщение.
- `line.rstrip("\n")` убирает символ конца строки.
- Цикл `for` заканчивается, когда сервер закрыл соединение. Если сервер «упал» резко, чтение выбрасывает `ConnectionResetError` — это разновидность `OSError`, поэтому мы её ловим. В обоих случаях добавляем в список строку о потере связи, чтобы пользователь увидел её на странице.

Здесь `sock` не передаётся в функцию аргументом, как в `client.py`: функция берёт общую переменную `sock`, объявленную выше. Так же устроены функции Flask: они тоже пользуются общими `sock` и `messages`.

### Страницы

```python
@app.route("/")
def index():
    return render_template("index.html")
```

Главная страница: окно с сообщениями и форма. Данные ей не нужны: сообщения покажет iframe.

```python
@app.route("/messages")
def show_messages():
    with messages_lock:
        shown = list(messages)
    return render_template("messages.html", messages=shown)
```

Страница только со списком сообщений. `list(messages)` делает **копию** списка под замком. Шаблон будет перебирать уже копию, без замка. Так замок держится доли миллисекунды, и поток приёма не ждёт, пока соберётся страница.

### Отправка

```python
@app.route("/send", methods=["POST"])
def send():
    text = request.form.get("text", "").strip()
    if text:
        sock.sendall((text + "\n").encode("utf-8"))
    return redirect(url_for("index"))
```

- `request.form.get("text", "")` — текст из поля формы с `name="text"` (урок 21).
- `sock.sendall((text + "\n").encode("utf-8"))` — та же строка, что в `client.py` после `input()`. Не забываем `\n`: по нему сервер понимает, где кончилось сообщение.
- Пустые сообщения не отправляем: `required` в форме проверяет браузер, но запрос можно отправить и в обход формы. Сайт не доверяет тому, что пришло из браузера.
- `redirect` — правило POST → redirect → GET из урока 21: после отправки возвращаемся на главную, и F5 не отправит сообщение второй раз.

Своё сообщение в `messages` мы **не добавляем**. Функция `broadcast` в `server.py` рассылает каждое сообщение всем клиентам, в том числе автору. Оно придёт обратно через `receive_loop`, уже с подписью-адресом, как у всех остальных.

### Запуск

```python
def main():
    sock.connect((HOST, PORT))
    print(f"Подключились к серверу чата {HOST}:{PORT}")

    threading.Thread(target=receive_loop, daemon=True).start()

    app.run(port=WEB_PORT)
```

- Порядок важен: сначала подключиться к серверу и запустить поток приёма, и только потом `app.run()`. Он работает бесконечно, как цикл `while True` с `input()` в `client.py`, поэтому код после него не выполнится, пока сайт не остановят.
- `daemon=True` — поток приёма не мешает программе завершиться по Ctrl+C (урок 2).
- Подключиться к серверу учителя — написать его IP в `HOST`, например `HOST = "192.168.1.10"`.

#### Почему без `debug=True`

В уроках 19–21 мы запускали сайт с `debug=True`. В этом режиме Flask запускает программу **дважды**: первый процесс следит за изменениями файлов, второй обслуживает сайт и перезапускается после каждого сохранения. Для сайта урока 21 это было удобно. Здесь же каждый запуск программы — это `sock.connect`, и сервер увидел бы двух клиентов вместо одного, а после каждого сохранения файла — ещё одного. Поэтому сайт запускаем без отладки, а после изменений в коде перезапускаем вручную (Ctrl+C и снова `python app.py`).

### Сколько здесь потоков

| Поток | Что делает | Откуда взялся |
|---|---|---|
| Главный | `app.run()`: ждёт запросы браузера | запуск программы |
| `receive_loop` | ждёт сообщения от сервера чата | `threading.Thread(...)` в `main()` |
| По одному на запрос | собирает страницу `/` или `/messages`, обрабатывает `/send` | Flask создаёт их сам |

Это тот же приём, что в `client.py`: одно направление (приём) — в своём потоке, другое (отправка) — в главном. Только «главный» теперь не ждёт `input()`, а отвечает на запросы браузера. А «по потоку на запрос» — это то же, что «по потоку на клиента» в `server.py`.

## Разбор шаблонов

### `templates/index.html`

```html
<iframe src="{{ url_for('show_messages') }}"></iframe>

<form method="post" action="{{ url_for('send') }}">
  <input name="text" placeholder="Сообщение…" autocomplete="off" required autofocus>
  <button type="submit">Отправить</button>
</form>
```

- **`<iframe>`** — «окно», в котором показана другая страница, здесь `/messages`. Это отдельная страница со своим `<head>`, и браузер загружает и перезагружает её отдельно от главной.
- Форма — как в уроке 21, только поле одно. `autocomplete="off"` — чтобы браузер не подсказывал прошлые сообщения, `autofocus` — курсор сразу в поле, можно печатать.
- После отправки сайт делает redirect на `/`, главная загружается заново, а вместе с ней и iframe. Поэтому своё сообщение обычно видно сразу.

### `templates/messages.html`

```html
<meta http-equiv="refresh" content="2">
...
{% for text in messages|reverse %}
  <p>{{ text }}</p>
{% else %}
  <p><i>Сообщений пока нет. Напишите первым!</i></p>
{% endfor %}
```

- **`<meta http-equiv="refresh" content="2">`** — просьба к браузеру: «через 2 секунды загрузи эту страницу заново». Загрузил — опять 2 секунды — опять загрузил. Так новые сообщения появляются сами, без JavaScript.
- Тег стоит в `messages.html`, а не в `index.html`. Если перезагружать всю главную страницу, вместе с ней пропадёт текст, который человек набирает в форме. А так перезагружается только окно iframe, форма остаётся нетронутой.
- `messages|reverse` — новые сообщения сверху. После каждой перезагрузки iframe показывает начало страницы. Будь новые внизу, после каждого обновления их пришлось бы прокручивать заново.
- `{% for %} ... {% else %}` — блок `else` срабатывает, если список пустой (урок 20).
- `{{ text }}` — Jinja **экранирует** текст: `<script>` превращается в `&lt;script&gt;` и показывается как обычные символы. Сообщения в чат пишут другие люди, и без экранирования любой мог бы запустить свой JavaScript в чужих браузерах.

## Ограничения (и что дальше)

- **Один сайт — один участник чата.** Сокет `sock` один на всю программу. Откройте сайт в двух вкладках: обе покажут одно и то же, а сервер увидит одного клиента. Поэтому каждый ученик запускает свой сайт у себя, как раньше запускал `client.py`. Сделать, чтобы каждая вкладка была отдельным участником, можно: нужно своё подключение на каждого пользователя. Так и сделано в уроке 24.
- **Нет имён.** Сервер урока 3 подписывает сообщения адресом клиента. Имя можно приписать к тексту прямо на сайте (задание 1), а по-настоящему имена появляются в уроке 5.
- **Обновление раз в 2 секунды** — лишние запросы, даже когда ничего не происходит, и задержка до 2 секунд. Лучше: опрос через `fetch` без перезагрузки страницы (урок 22) и WebSocket, когда сервер сам присылает новое сообщение в браузер (урок 24).
- **Сообщения живут в памяти.** Перезапустили сайт — список пуст. Сервер урока 3 историю тоже не хранит (база данных — урок 6).
- **Всё в одном файле, настройки — константами.** Пока программа маленькая, это удобно. Когда кода станет больше, его разложат по пакетам и вынесут общее (например, отправку строки) в отдельный модуль — урок 4. Этот же сайт в такой структуре — урок 21b.
