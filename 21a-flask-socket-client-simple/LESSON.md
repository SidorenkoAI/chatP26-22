# Урок 21a. Веб-клиент для сокет-чата урока 3: консоль → страница в браузере

## Цель

Соединить сокет-чат и сайт самым простым способом. Берём однофайловый сервер чата из урока 3 и **не меняем в нём ни строчки**. Консольный клиент `client.py` заменяем маленьким сайтом на Flask: вместо `input()` — форма, вместо `print()` — список сообщений на странице. Браузер и консольные клиенты переписываются в одном чате.

Никаких пакетов, классов, баз данных, JSON, входа по паролю и JavaScript. Протокол тот же, что в уроке 3: строки текста, разделённые `\n`.

Это урок-мостик для групп, которые прошли уроки 1–3 и 19–21, но ещё не дошли до урока 4 (структура проекта). Тот же урок на коде урока 4 — [урок 21b](../21b-flask-socket-client/LESSON.md).

## Перед началом

- Из урока 3 — `server.py` и `client.py`, **без изменений**.
- Из урока 21 — Flask, формы, POST → redirect → GET. Поставить Flask: `pip install -r requirements.txt`.
- Новые файлы:
  - `app.py` — сайт, он же клиент чата;
  - `templates/index.html` — страница с окном сообщений и формой;
  - `templates/messages.html` — только список сообщений, обновляется сам.
- Три терминала в папке урока: `python server.py`, `python client.py`, `python app.py`.

## Теория (10 минут)

- **Вспомнить `client.py` урока 3.** Он делает три вещи: подключается к серверу (`connect`), в отдельном потоке печатает всё, что пришло (`print`), а в главном цикле отправляет то, что ввели (`input`).
- **Идея урока.** Сайт на Flask тоже может быть клиентом чата. Он подключается к серверу так же, как `client.py`. Только пришедшие сообщения он не печатает, а складывает в список, а текст для отправки берёт не из `input()`, а из формы.
  ```
  браузер ──HTTP (форма)──► app.py ──сокет──► server.py (урок 3) ◄──сокет── client.py
  ```
- **Почему браузер не подключается к серверу чата сам.** Браузер умеет только HTTP (и WebSocket, урок 24). «Голый» TCP-сокет, как у `client.py`, ему недоступен. Поэтому посередине — наш сайт: с браузером он говорит по HTTP, с сервером — через сокет.
- **Как новые сообщения попадут на экран без JavaScript.** Сообщения показываем на отдельной маленькой странице, которая сама перезагружается раз в 2 секунды (`<meta http-equiv="refresh">`). Эту страницу вставляем в главную через `<iframe>` — «окно» с другой страницей внутри. Форма снаружи iframe, поэтому набранный текст не пропадает.

## Пошаговый план занятия

1. **Запустить урок 3.** В двух терминалах: `python server.py` и `python client.py`. Написать пару сообщений. Открыть `client.py` и найти в нём `connect`, `print` и `input`: именно их сейчас и заменим.

2. **Сайт, который только читает.** Создать `app.py`. Константы и подключение — как в `client.py`:
   ```python
   HOST = "127.0.0.1"
   PORT = 5555
   WEB_PORT = 5000

   sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
   messages = []
   messages_lock = threading.Lock()

   def receive_loop():
       incoming = sock.makefile("r", encoding="utf-8", newline="\n")
       for line in incoming:
           text = line.rstrip("\n")
           with messages_lock:
               messages.append(text)

   @app.route("/messages")
   def show_messages():
       with messages_lock:
           shown = list(messages)
       return render_template("messages.html", messages=shown)
   ```
   И `main()`: `sock.connect(...)`, поток с `receive_loop`, `app.run(port=WEB_PORT)`. Шаблон `messages.html` пока без тега `<meta http-equiv="refresh">`.

   Запустить `python app.py`. В терминале сервера появился ещё один клиент: это наш сайт. Открыть `http://127.0.0.1:5000/messages`, написать что-нибудь из `client.py` и нажать F5 в браузере. Сообщение на странице! Половина клиента готова: `print()` заменили страницей.

   Положить рядом `receive_loop` из `client.py`: отличается одна строка. И появился замок, как у `clients` в `server.py`: список `messages` меняет поток приёма, а читают потоки Flask (урок 21).

3. **Отправка.** Добавить форму в `index.html` и маршрут `/send`:
   ```python
   @app.route("/send", methods=["POST"])
   def send():
       text = request.form.get("text", "").strip()
       if text:
           sock.sendall((text + "\n").encode("utf-8"))
       return redirect(url_for("index"))
   ```
   Строка с `sendall` — та же, что в `client.py` после `input()`. На главной — `<iframe src="/messages">` и форма. Отправить сообщение из браузера: оно появилось в `client.py`. Вторая половина готова: `input()` заменили формой.

   Обратить внимание: своё сообщение мы в список **не добавляем**. Оно приходит обратно от сервера, как и в `client.py`: функция `broadcast` в `server.py` рассылает каждое сообщение всем, в том числе автору.

4. **Автообновление.** Написать что-нибудь из `client.py`: в браузере ничего не меняется, пока не нажмёшь F5 или не отправишь своё. Добавить в `<head>` шаблона `messages.html`:
   ```html
   <meta http-equiv="refresh" content="2">
   ```
   Теперь сообщения из консоли появляются сами. Начать набирать текст в форме и подождать: текст не стирается, потому что перезагружается только iframe.

   Почему новые сообщения сверху (`messages|reverse`)? После каждой перезагрузки iframe показывает начало страницы. Если бы новые были внизу, их пришлось бы каждый раз прокручивать.

5. **Почему без `debug=True`.** Временно написать `app.run(port=WEB_PORT, debug=True)` и перезапустить сайт. В терминале сервера — **два** новых клиента! В режиме отладки Flask запускает программу дважды: второй экземпляр следит за изменениями файлов. Значит, и `sock.connect` выполняется дважды. Вернуть как было.

6. **Безопасность.** Из `client.py` отправить `<b>жирный</b>` и `<script>alert(1)</script>`. В браузере — обычный текст: шаблон экранирует его сам (урок 20). Иначе любой участник чата мог бы выполнить свой JavaScript в браузерах всех, кто сидит через сайт.

7. **Общий чат в классе.** Учитель меняет в своём `server.py` строку `HOST = "127.0.0.1"` на `HOST = "0.0.0.0"`, чтобы к серверу можно было подключиться с других компьютеров, и запускает его. Ученики в **своём** `app.py` пишут в `HOST` IP-адрес компьютера учителя, запускают сайт и открывают `http://127.0.0.1:5000/`. Часть класса — в браузере, часть — в консоли, чат один.

8. **Обсудить ограничения.**
   - Сайт — это **один** клиент чата. Откройте его в двух вкладках: сервер видит одного участника, и обе вкладки показывают одно и то же. Поэтому каждый запускает свой сайт у себя.
   - Сообщения подписаны адресом вида `('127.0.0.1', 53211)`. Имена — в задании 1 (пока без изменений сервера) и в уроке 5 (по-настоящему).
   - Перезагрузка каждые 2 секунды — это много лишних запросов (F12 → Network). Как сделать лучше: опрос через `fetch` (урок 22) и WebSocket (урок 24).
   - Адреса и порты зашиты в код константами. Чтобы подключиться к другому серверу, приходится править файл. В уроке 4 их можно будет передать при запуске (`argparse`), а сайт из этого урока там разложен по пакетам — урок 21b.

## Контрольная точка

- Сообщение, отправленное из браузера, появляется в `client.py`, и наоборот.
- Сообщения из консоли появляются в браузере сами, без F5, а набранный в форме текст при этом не пропадает.
- В терминале сервера сайт виден как **один** клиент.
- `<script>` из консоли показан в браузере как текст.

## Частые проблемы

- **`ConnectionRefusedError: [WinError 10061]` при запуске `app.py`.** Сервер чата не запущен или в `app.py` другой `PORT`, чем в `server.py`. Сначала `python server.py`, потом сайт. Понятное сообщение вместо этой ошибки — задание 4.
- **Сайт ученика не подключается к серверу учителя (`TimeoutError` или `ConnectionRefusedError`).** В `server.py` учителя осталось `HOST = "127.0.0.1"`, в `app.py` ученика неверный IP, или порт закрыт брандмауэром Windows на компьютере учителя (разрешить Python при первом запуске сервера).
- **`ModuleNotFoundError: No module named 'flask'`.** Не установлен Flask или не активировано виртуальное окружение: `pip install -r requirements.txt`.
- **`TemplateNotFound: index.html`.** Нет папки `templates` рядом с `app.py`, или она называется иначе (`template`, `Templates`).
- **В терминале сервера два клиента от одного сайта.** Включён `debug=True` (шаг 5).
- **Текст в форме стирается каждые 2 секунды.** Тег `<meta http-equiv="refresh">` попал в `index.html`, а должен быть в `messages.html`.
- **Внутри iframe открылась вся страница целиком (с формой) или ошибка 404.** В `src` у iframe не тот адрес: нужен `/messages`.
- **Сообщение пришло, но «прилипло» к следующему, или не пришло вовсе.** Забыли `+ "\n"` при отправке: сервер ждёт конца строки (урок 3).
- **Остановили сервер, а сайт при отправке показывает `500 Internal Server Error`.** Сайт пытается писать в закрытое соединение. В окне сообщений при этом есть «Соединение с сервером потеряно». Перезапустить сервер и сайт; аккуратная обработка — задание 4.
- **Своё сообщение появилось не сразу после «Отправить».** Сервер присылает его обратно за доли секунды, а страница иногда успевает загрузиться раньше. Через 2 секунды iframe обновится, и оно появится.
- **`Address already in use` / порт 5000 занят** (на macOS его занимает AirPlay). Поменять `WEB_PORT` в `app.py`, например на 5001.
